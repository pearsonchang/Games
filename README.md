# PLAYROOM

包含金币扫雷、小火箭、三骰挑战、闪电跑道、星际赛马、星际老虎机和星际矩阵的网页游戏 Demo。使用纯 HTML、CSS、JavaScript；所有积分均为浏览器会话内的模拟积分，刷新后重置，没有账户、充值、提现或真实资产交易。

## 本地运行

编辑 `src/`，发布文件由构建生成到 `dist/`。项目没有 npm 包依赖，不需要先执行 `npm install`。需要 Node.js 22 或更高版本。

```sh
npm run build
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8765/`，默认进入已选定的 A1 高能街机大厅（冰蓝按钮、亮紫主舞台、太空头像与七款游戏）。`/index.html` 使用同一首页；`/lobby-demo.html?look=festival` 保留为设计预览，两者共用同一套样式和呈现。不要双击 HTML 用 `file://` 打开；积分管理和 iframe 通信依赖同源 HTTP 页面。单独打开游戏 HTML 不会创建大厅的积分会话。

修改源码后重新运行构建并刷新预览。仅做快速开发预览时可把服务器目录改为 `src`；最终验证使用 `dist`。

检查命令：

```sh
npm run check
npm test
npm run build
```

`check` 检查 JavaScript 语法、HTML/CSS 与控制器里直接引用的本地资源、文件名大小写，以及十三个入口（七款游戏、大厅、配色对比和配色体验、三种大厅设计预览页面）。它不是完整的 HTML/CSS 解析器，也不代替浏览器交互检查。`test` 自动执行 `tests/` 中的全部 Node 测试。`build` 先检查源码并运行全部测试，再生成带自动资源版本号的静态文件，检查产物后替换 `dist/`。检查失败会保留上一次可用的预览；部署会失败。`dist/` 已从 Git 跟踪中移除，不要直接编辑。

构建无第三方依赖，`node scripts/build.cjs` 与 `npm run build` 等价。版本号由完整源码和转换逻辑计算；相同源码重复构建的内容一致。资源路径保持原文件名，用自动生成的 `?v=` 更新缓存；这不是文件名哈希方案。

## Vercel 部署

在 Vercel 导入 GitHub 仓库 `pearsonchang/Games`，使用下列设置：

| 设置 | 值 |
| --- | --- |
| Framework Preset | Other |
| Root Directory | 仓库根目录 `./` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | 留空，跳过安装 |
| Environment Variables | 当前 Demo 不需要 |

根目录的 `vercel.json` 已保存框架、检查命令、安装行为、输出目录和 URL 设置。Root Directory 是 `./`，不要选择 `dist`；本地工作区路径 `outputs/coinsweeper` 不是这个 GitHub 仓库内的子目录。

Vercel 构建时从 `src/` 生成 `dist/`，最终仅发布 `dist/`。源码说明、测试、`.openai/hosting.json` 和构建脚本不会作为网页资产发布。保留 `.openai/hosting.json` 供已有 Sites 网站使用；Vercel 使用自己的 `vercel.json`，两者可以共存。

`cleanUrls: true` 支持 `/palettes` 等无扩展名地址；现有 iframe 的 `.html` 地址会同源重定向到对应页面。`trailingSlash: false` 保持资源相对路径的目录层级。不要添加将全部请求重写到 `/index.html` 的 SPA 通配规则，否则独立游戏页面或资源路径可能被错误替换。

当前 Vercel 规则下，新项目的第一次部署属于 Production。之后推送非生产分支或创建 PR 会产生 Preview 部署，推送生产分支（通常是 `main`）会更新 Production。需要“只做预览”时，在已有项目上用功能分支或 PR。部署访问权限在 Vercel 项目中单独配置，原 Sites 的私有访问权限不会自动迁移。

部署后从根路径进入大厅，确认七款游戏都能进入、积分扣除/结算正常、返回大厅正常；另检查 `/palettes`、浏览器刷新和资源是否有 404。配置已可本地验证，实际 Vercel 地址和访问权限需在导入并完成部署后确认。

官方文档：[项目配置](https://vercel.com/docs/project-configuration/vercel-json)、[构建设置](https://vercel.com/docs/builds/configure-a-build)、[预览与生产环境](https://vercel.com/docs/deployments/environments)。

## 代码结构

- `src/platform-catalog.js`：游戏目录、名称和入口。
- `src/lobby-preferences.js`：只保存收藏、最近三款游戏和探索足迹；校验游戏 ID，存储不可用时回退到页面内存。
- `src/game-load-guard.js`：等待游戏就绪、加载超时和重试状态；重试只刷新 iframe，不重置当前对局和积分账本。
- `src/platform-wallet.js`：会话积分账本，整数小数位记账、金额校验、交易去重。
- `src/platform-bridge.js`：游戏实例、可信 iframe 消息、轮次检查与一次性结算。
- `src/platform-view.js`：大厅、奖励、记录和帮助的页面内容。
- `src/platform.js`：连接上述模块，处理导航和画面同步。
- `src/*-engine.js`：独立的概率与结算逻辑，可注入时钟和随机数。
- `src/rocket.js`、`dice.js` 等：游戏画面、交互和音效。
- `src/design-tokens.css`：当前 A 方案公共颜色；`theme-a.css` 和 `lobby-a.css` 消费这些变量。
- `src/lobby-station.css`：星际游乐站大厅、推荐卡、分类、收藏、足迹及移动端排版。
- `src/*.webp`：压缩后的游戏素材，构建不依赖图片处理工具。
- `scripts/build.cjs`：检查、测试、生成静态产物；`build-static.cjs` 负责可重复的版本处理。
- `tests/`：概率、游戏状态、表现层、账本、消息协议和构建测试。
- `docs/rocket-probability.md`：小火箭 97% 理论返还率的推导与边界。

## 星际老虎机 Demo

大厅第六款游戏，也可直接打开 `/slots.html` 独立试玩。每局 50 模拟积分，三列独立随机，只结算中间横线。两个相同图案返还 50 积分；三个相同按环星/推进器/星晶/卫星/跃迁门/星际徽章 分别返还 4/7/12/20/35/100 倍（含投入），最高 5,000 积分。三个不同则奖励为 0。

六种图案的权重依次是 8、5、3、2、1、1，总权重 20。全部 8,000 种等权组合穷举得到理论返还率 97%、每局净收益期望 −1.5 积分。转轴依次停下并自动结算；支持空格操作、音效开关与减少动态效果设置。无需账户或后端，刷新会重置体验积分。

老虎机使用独立的机械转轴与和弦音效；两同号返还与六种三连分别触发不同反馈。奖励图鉴中的“试听与特效预览”可直接比较全部效果，不调用游戏引擎，也不扣除或发放积分。静音、离开页面或切换效果时会清理声音与粒子。

## 星际矩阵 Demo

第七款游戏，`/matrix.html` 可独立试玩；大厅与其他游戏共享本次体验积分。原版 `/slots.html` 保留。

5 列 × 3 行，每格独立按 30/25/20/15/7/3 的权重抽取环星、推进器、星晶、卫星、百搭、徽章。每局投入 50，固定 10 条线，每线 5 积分。从最左列起连续 3–5 个同图案才奖励。连线倍率依次为环星 5/8/12、推进器 6/10/16、星晶 10/15/22、卫星 10/17/25；百搭可替代普通图案，每线只取最高奖励，多线奖励相加。全盘徽章 3/4/5+ 个额外返还 100/250/1,000，取一个档位，百搭不替代徽章。

线性期望允许直接相加十条线的期望，即使它们共用格子。单线穷举 6^5 个符号序列并按权重计算，得到连线返还率 94.80362536%；15 格徽章数量服从 Binomial(15, 0.03)，徽章奖励贡献 2.2136063474%。总理论返还率 **97.0172317074%**，每局平均净收益约 **−1.49138 积分**。数学模型假设各格独立、随机源均匀；当前 Demo 使用 `Math.random()`，不涉及链上或真实资产。

结果在开始时抽出，五列依次落定，2.6 秒后统一结算。界面高亮中奖路径与前缀格子，可切换逐条查看；部分返还明确显示负净收益。图鉴用六个固定示例展示直线、V 形、百搭、徽章、多线叠加和三连回本，使用真实结算函数，独立于游戏会话、不扣分、不发积分。概率和结算测试见 `tests/matrix.test.cjs`。

2026-10-05 的奖表调整提高了三连返还，降低部分四连、五连奖励。星晶和卫星的单线三连均返还 50，明确按回本呈现；环星和推进器单线三连返还 25/30，仍明确显示净亏。抽样权重、徽章奖励和每局独立性不变，不按余额、玩家历史或连输次数改变结果。复用生产抽样/结算函数，以固定 xorshift32 种子 0x5ac817d3 模拟 2,000,000 局，新分布约为零返还 40.45%、部分返还 15.40%、回本 10.78%、净赚 33.36%；回本或净赚合计从旧版约 30.96% 提高到 44.14%。这些是模型模拟估计，不是用户留存率，也不保证有限局数回报。精确期望与固定样本分布回归由 `tests/matrix.test.cjs` 验证。
